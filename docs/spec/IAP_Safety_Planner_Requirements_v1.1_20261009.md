# IAP Safety Planner 开发需求说明书

**版本：1.1｜日期：2026-10-09｜状态：待实现的修订需求基线**  
**本轮定位：完整性感知 EGO 的轻量闭环改造，保留既有离散执行检查。**

> 路线允许朝未知空间延伸；只提交通过既有实际曲线检查、具有真实静止末端的局部运动；advisory 参与选路，不单独决定执行许可。
>
> 本版不实现“连续时间完整机体包络全部已观测”的证明，不承诺任意盲区可达、最小 PL 路线或实飞安全资格。

## 0. 使用方法与修订效力

本文件是可以独立用于开发的完整替代稿，不需要把 v1.0 与本版拼接执行。保留 R01–R12 编号用于追踪，但要求以本版正文为准。特别是 **R06、R10、R11 以及测试计划已改写**：v1.0 中的连续包络实现、三点包络探针、对应 T04 和 `checkExecutionTube()` 不再是本轮交付要求。

“必须／不得”表示行为契约；“建议”表示允许等价替换的实现方式。文中的新代价函数、恢复上限、结果字段和策略常量是设计决定，不是现有功能，也不是已经验证的最优配置。Markdown 为主稿，Word 为同内容阅读版。

### 本轮执行边界补充（2026-10-09）

以下决定覆盖正文中“先选一个观察端点再搜索”等较早措辞；不另设设计体系。

1. **guide 受阻不等于已观测无路。** 分别报告当前 guide 的观测阻塞、执行语义连接搜索未找到结果，以及搜索超时无法判断。乐观 guide 截短不足不能直接报告全局无路或无限等待。在原共享预算／恢复额度内，仅一次复用同一 A* 的执行语义连接搜索，优先连接可继续推进的已观测局部目标；确需改善观测时才选观察目标。只交付一条 guide，不增加候选池、搜索器或恢复状态机，也不放宽执行条件。
2. **观察候选必须考虑连接证据。** 最多八个廉价候选，结合已知障碍、执行观测状态及现有连接证据删除明确不可连接者。复用同一 A* 多目标接口，以一次有界连接搜索找到一个可达且正收益的目标，输出一条路径，再仅对此目标进行一次 EGO 求解。不得逐个完整搜索／优化八个目标。端点可用不代表连接可用，预算耗尽不代表不可达，实际收益依动作完成后的相关新观测判断。此搜索与上一条共同消耗同一个恢复机会，不能各加一次。
3. **后端、硬检查与提交必须留有实际时间。** 总预算仍 1.5 s、累计搜索仍 1.0 s、原修复额度不重置。沿用 PlanningBudget，以一次冷计时及必要修复前后对照确定正常搜索保留量、恢复准入和质量评估截止；具体实现分配记录在现有流程文档。恢复无剩余预算返回 BUDGET，不能新建预算再搜索；可选质量评估／修正不得挤占最终硬检查。正常搜索不能先耗尽全部额度再启动必然不能完成的恢复。不新增预算管理器或成排开关，不预设未经验证的低耗时指标。

### 1.2 需要解决的四类问题

**搜索资格与执行资格混用。** `queryPlanningCell()` 的未观测拒绝同时影响目标、搜索和实际曲线。路线未知不应自动失去规划意义，但未知也不能获得执行许可。[C1,C2]

**advisory 的 strict/fallback 语义。** 原代码将 warning 在首轮当作拒绝条件，在 fallback 中才作为高代价。新策略改为统一有限代价，属于行为变更，不是纯重构。[C3]

**目标与观测策略不匹配。** 状态资料报告原终点未被五份末端扫描覆盖，且局部距离小幅减少没有带来任务到达。该报告支持设计观察接近，但不能证明全局无路或确定某个动作必然成功。[U1]

**停止授权与实际运动脱节。** 原正常停止空间启发式与保护制动生成器不是同一实际曲线；服务端到时清零也不是此前曲线已停稳。本轮用新提交曲线自身的静止末端收束正常失败处理。[C2,C4,C5,C6]

### 1.3 本轮范围

本轮只实现：语义分离、风险软代价、guide 到受检局部段、静止末端、统一检查与提交、一个针对观测阻塞的受限恢复函数，以及最小必要验证。

不做：完整连续扫掠证明、重写自由空间模型、GLIO/FGO 改造、PL 来源校准、噪声调整、MINCO/BLOM 替换、通用 frontier 探索、信息增益优化、独立 nominal/backup 双求解器、动态障碍预测和新执行协议。

原四分叉任务、原 seed、原起终点及到达规则保持。终点 `[18,0,1.5]` 只出现在任务配置或 fixture 中，不硬编码进算法。[U1]

## 2. 能力契约与唯一职责

### 2.1 本版实际能承诺什么

本版本的检查结论是：

**最终发送的 B-spline 具有数值一致的起点与静止末端；满足既有逐轴动力学约束；通过既有实际曲线采样、已知障碍净空、运动质量、时效和接续检查。**

此结论限定于实际检查模型、输入与时刻。它不等于整条轨迹在连续时间、完整机体扫掠体积、所有故障和真实环境中均已证明安全。记录建议使用 `CHECKED_MOTION`，而不是无条件的 `SAFE`。

| 层面 | 本轮要求 | 不得推导 |
|---|---|---|
| 路线偏好 | 有效 PL 通过固定函数影响 A* 代价和 guide | 选中全局最低 PL／最高置信度路线 |
| 执行检查 | 实际曲线通过规定离散检查并以静止状态结束 | 完整扫掠无碰撞证明、任意失效下安全停车 |
| 任务结果 | 用原规则判断真实执行到达 | 由发布数、guide 到终点或局部停稳推定到达 |
| 开发验收 | 少量定向回归与原任务结果可复现 | 统计完整性、成功率优势或实飞资格 |

采用静止末端是本版的工程取舍。FASTER 原论文指出已知自由空间内的停止条件可能限制速度；其双轨迹架构和安全结论不直接继承给本系统。[R1]

### 2.2 条件失效不能靠旧轨迹“自证安全”

普通求解失败与环境／估计失效必须分开。在地图、运动估计和控制假设继续成立时，可以沿旧受检曲线走向其停止末端。新障碍、跟踪越界、证据撤销、估计器停更等发生后，旧检查不再自动有效。

`current_motion_error_proxy_m` 继续叫误差代理，不升级为故障覆盖 PL。几何 tracking reserve、起点接续容差、运行告警阈值和真实停车容差各自保留含义。若数值不一致，只记录限制与具体冲突，不用较大告警阈值证明较小净空预留充分。

### 2.3 所有权约定

| 事项 | 唯一责任方 |
|---|---|
| 占据／观测事实、来源与物理 generation | GridMap / RegisteredLidarWindow |
| PL 数值计算及有效性来源 | 既有 Predictor / 当前监测；GridMap 只保存与提供绑定查询 |
| 一轮冻结输入与累计预算 | 现有 PlanningView / PlanningBudget，由 manager 绑定 |
| 路线可通行与边代价 | A* 的路线查询入口及共享代价函数 |
| guide 拟合、参考跟踪与有限优化 | 现有 EGO 后端 |
| 候选是否满足执行提交条件 | manager 中一套硬检查与提交逻辑 |
| 任务／规划触发及对执行的监督 | 原 FSM，消费实际反馈，不自行假定激活 |
| accepted/pending/active 的实际切换与命令 | traj_server；planner 的本地镜像以反馈为准 |

“一套检查”指一个政策实现，不是只调用一次。规划阶段与最新发布阶段需要不同时间的检查；server 的消息合法性和边界防御也必须保留。

## 3. 主流程与资源形态

```text
原 FSM 产生真实规划事件
  → 消费反馈，冻结一个 PlanningView 和共享预算
  → 原任务目标 / 局部路线目标
  → 同一个 A*：已知障碍禁止，未知与 advisory 有限代价
  → 一条 guide
  → 选择按既有执行查询可用的连续局部前缀
  → EGO 初始化、参考跟踪、优化，生成真实静止末端
  → 一套实际曲线硬检查 + 独立质量报告
  → 最新相关走廊与接续检查
  → 原提交、发布、激活反馈和运行监督
```

无有效前缀且原因确为观测阻塞时，可以调用一次执行语义连接恢复，优先已观测推进，必要时观察接近。候选发生可修复的几何／动态问题时，可以执行一次有界修正。这是两种有条件的处理，不是“任何失败都先修正、再观察、再重搜”的串行重试链。

任何失败均不覆盖 active。保留旧运动的前提是它仍符合当下检查条件；条件失效时走既有保护处理并明确报告。

## 4. R01：分离事实、路线查询与执行查询

### 4.1 行为矩阵

| 条件 | 路线搜索 | 本版实际执行检查 |
|---|---|---|
| 已知 raw / inflated 障碍 | 拒绝 | 拒绝 |
| 地图内自由且净空充分 | 可搜索 | 采样点观测、时效等条件满足后通过 |
| 地图内物理未知 | 允许路线意图，增加有限代价 | 保留既有采样点未观测拒绝 |
| 地图外或 pool 外 | 不扩成无限搜索 | 拒绝 |
| advisory warning / degraded | 有限较高代价 | 不单独拒绝或急停 |
| advisory 缺失 / stale / 版本不匹配 | 明确保留状态，使用缺失代价 | 不单独改变物理结论 |
| motion、frame 或物理输入失效 | 不启动新的在线运动求解 | 不授权新正常运动 |

路线未知与 PL 缺失是两个独立字段。未知体素不能被推断为卫星无遮挡或 LiDAR 观测充分。

### 4.2 最小接口改造

可保留 `queryPlanningCell()` 作为执行入口，增加薄的 `queryRouteCell()`；或者明确重命名为 route/execute 两入口。两者共享事实与净空算法，不分别维护地图、来源、时效或缓存政策。

**禁止将 `ENVIRONMENT_UNOBSERVED` 直接改成 `OK` 后交给 A\*。** 原执行入口在未观测处分支返回，后续障碍、净空或其他条件可能尚未计算。路线入口必须从原始事实检查已知障碍与净空，不能将提前返回的执行结果误当作“除了未知其余都合法”。[C1]

建议 `RouteCell` 包含 `traversable`、`physical_unknown`、`cost` 和原因；不得隐式转换成执行许可。`ExecutionCheck` 默认未完成／不通过，只有全部必需检查完成才置为通过。

同一冻结视图中的查询结果可复现。缓存只复用其键能完整描述的内容；精确位置不同不得仅凭同一体素地址复用精确距离，旧风险版本不得假扮新版本。

**验证：T1。**

## 5. R02：统一有限 advisory 代价

### 5.1 保留 v1.0 的工程函数，避免再次扩大调参

路线弧长代价：

`J_route = ∫ [m_adv(x) + λ_u · I_physical_unknown(x)] ds`。

OFF 时仅 `m_adv=1`，未知政策、观测恢复、末端策略及所有硬检查不变。未知附加代价 `λ_u=1.5` 作为未校准开发默认；沿用 v1.0，不另外增加权重矩阵。

```text
r = max((HPL + reserve_h) / H_budget,
        (VPL + reserve_v) / V_budget)

有效且数值有限、非负：
  0 ≤ r ≤ 1 : m_adv = 1 + 0.5 r
      r > 1 : m_adv = min(3, 1.5 + 1.5 (r - 1))

无有效数值且明确 predicted-degraded：m_adv = 3
其他缺失 / stale / 失配：m_adv = 现有 unknown_multiplier
```

budget 必须为正，reserve 合法；非法数值不得进入有效分支。缺失代价只属于规划，不回写 HPL/VPL，不把 NaN 改成零。

这个函数对有效 `r` 连续、非减，但并非处处可微；体素场、有效性变化和截断仍可能不连续。不得把“连续软代价”解释成已得到空间光滑 PL 场或可靠 PL 梯度。上限 3 使极大值不再继续区分，缺失默认值可能低于明确退化代价；二者都是有限偏好的已知取舍，不是最小风险保证。

### 5.2 一处函数，所有调用一致

A* 边积分、guide 前缀与曲线质量评估使用同一函数和单位。删除新主线中 warning 的边拒绝及 `AdvisoryFallback` 通行许可；标签保留用于诊断／旧日志，不再左右可通行性。[C3]

非负边成本不意味着搜索已求得全局最优。沿用 weighted search 或预算中提前返回时，按实际算法填写 `optimality_proven`。不能因代价为软约束就宣称最安全路径。

保留当前 H/V budget、reserve、来源噪声、prior OFF 等有效运行配置。物理净空使用 motion error proxy，不悄悄用空间 advisory PL 替换。

## 6. R03–R04：目标、一条 guide 与局部前缀

### 6.1 R03：三个目标身份

必须区分 `mission_goal`、`route_target` 和 `committed_endpoint`。任务终点可以未观测；已知被占据时报告目标冲突，不改变任务终点。原 pool 外目标仍通过既有几何 horizon 选择局部路线目标，不扩大地图或搜索池。

保留真实位置在参考上的投影进度和原到达判据。普通局部停车、选中原目标、guide 到达原目标、参考进度到末端都不是任务到达。[C8]

当原目标位于本轮路线范围内且非已知障碍，正常搜索直接朝它规划，不让许多“便宜中间目标”与任务完成竞争。前缀不足由局部段选择解决，不再提前把未知原目标从路线层删掉。

不要求观察动作单步缩短到目标的欧氏距离；必要后退可以参与有限筛选。正常段的有效延伸可沿用 `max(2Δ,0.20 m)` 开发默认；临近原到达区域、停止及明确观察动作不受该下限阻塞。

### 6.2 R04：guide 的最小内容

guide 只保存点列／弧长索引、目标身份、frame、生成的 map/risk/policy 版本。一个 manager 最多保留当前使用的一条 guide；不新增候选路线列表、通道排名器或常驻路线管理进程。

沿 guide 使用现有执行点／边检查筛选连续前缀。遇到第一个拒绝就停止，不能跳过未知间隙连接到后面的已知自由点。这里的“连续前缀”指按路径顺序连续取用，不声称已证明时间和空间上的完整连续安全。

规划起点是当前绑定的 P/V/A，或旧曲线约定接续时刻的 P/V/A。起点不在旧 guide 上时，显式记录连接段；连接段不能因为很短就免检。

停止终点从可用前缀内选取。几何前缀只用于初始化，最终以真实 B-spline 硬检查为准。缩短前缀不保证更易制动，增加时间也不保证几何不变；调整后重查，不重新发放预算。

记录本次使用的 `[s_begin,s_end]` 及连接段。R11 的质量比较只使用这个同起终点参考，不能对完整远端 guide 积分后与短曲线比较。

### 6.3 搜索触发与可选复用

没有规划事件的 FSM 定时回调，不重新执行 A*。新任务、正常局部接续、既有风险重规划或相关物理变化才触发路线更新；不能只在碰撞后调用风险搜索，否则无碰撞的路线也可能一直不受 PL 影响。

跨轮复用 guide 是可选优化，不是本轮合入前置条件。复用仅代表几何参考：目标、frame、策略兼容，仍在原 horizon 内，连接段和待使用前缀在新 PlanningView 中重新检查；风险查询重新绑定。不复用旧执行结论、旧 PL 缓存或旧最优性标签。

保留既有风险重规划触发和节流。复用不得永久锁死旧路线，也不得因 risk_version 每次递增就高频重搜。不能以“复用 guide”为由绕过新的局部前缀与发布检查。

**验证：T1、T3；启用跨轮复用时在同一测试增加失效断言。**

## 7. R05：所有新曲线真实静止结束

### 7.1 数学边界与现有实现

所有新提交的正常／观察局部曲线必须满足绑定的起始 P/V/A，并以选定位置、零速度和零加速度结束。复用已有 `enforceBoundaryStates()` 和 `parameterizeToBspline()`；基线已经把边界等式与内部拟合分开，不重复开发。[C5]

建议沿用 v1.0 的数值容差：位置 `1e-5 m`、速度范数 `1e-5 m/s`、加速度范数 `1e-5 m/s²`。这些是代数一致性容差，不是实际停车或任务到达容差。scheduled 接续不得弱于现有服务端 P/V/A 检查。[C6]

最终控制点、knot 或时间分配发生变化后，重新计算实际端点导数及动力学。均匀三次端点公式不能不加条件地用于非均匀 knot。不得只看 `selected.velocity=0`、`terminal_stop=true` 或服务端到时发送的零速度。

分开 `ends_at_rest` 与 `reaches_mission_goal`。局部停止满足前者，不自动满足后者；已有按原目标位置生成的 `terminal_stop` 诊断必须迁移。[C4]

### 7.2 正常停止授权只保留一条主线

新主线全部具备真实静止末端后，退出以下正常候选授权调用：非零末速选择、基于 `terminalSpeedLimit()` 的末速授权，以及发布时直线 `terminal_stopping_space` 证明。

旧公式可以留作不授予许可的初始化启发式或历史 replay，但不能与新末端条件同时决定正常发布。迁移顺序是“新末端生成和验证完成 → 全部正常调用点迁移 → 旧授权路径退出”，不是先删检查。[C2,C4]

`planCheckedBrake()` 仍可作为实际危险时的替代动作生成器，但复用同一硬检查和提交路径。普通求解失败不再无条件生成一条临时制动。三次制动时长尝试本身不证明动作一定存在。

### 7.3 连续飞行与保守性

新曲线及时接续时不必实际停下；晚于窗口或旧曲线太短时，允许旧曲线先停，再由新鲜反馈发起下一条 `IMMEDIATE`。不得靠发送不满足边界的短接续或减小检查余量维持速度。

只记录本次任务的实际停顿、时长及接续结果，不增加必须匹配原版 EGO 速度的隐藏验收。控制反馈不满足已有停车容差时如实报告，不能用 setpoint 清零代替实测。

**验证：T3、T4。**

## 8. R06：保留既有实际曲线检查，明确离散边界

### 8.1 必须保留的硬检查

本轮复用 `assessTrajectory()`、相关 corridor 捕获和提交实现，检查最终实际 spline，而非 guide 或控制点。保留：数值／knot 合法性、实际端点、既有逐轴速度／加速度及 tolerance、采样点原始／膨胀占据、已知障碍净空、采样点未观测拒绝、现有坐标极值越界检查、motion／frame／时效、tracking 和接续身份。[C1,C2,C5]

维持既有实际曲线采样规则与端点访问；重构不能扩大采样间隔、漏掉最后不足一步的尾段或省略原极值越界检查。采样方案可以放在共用 helper，但不能顺手宣称变成连续证明。

采用原始体素中心距离时，保留原阈值：

`r_required = body_radius + tracking_reserve + error_proxy + √3·Δ/2`。

raw 净空与 inflated 快速拒绝各自沿用，半体素对角线不重复累计。误差代理、半径或已绑定地图信息非法时不得按通过处理；有明确定义的“有限邻域内无已知障碍”结果与“未计算／NaN”必须区分。

### 8.2 本轮明确没有证明的内容

采样中心格已观测且远离已知障碍，**不证明机体周围所有相交体素均已观测，也不证明采样时刻之间没有未知薄片或碰撞**。地图漏检、配准误差、未来误差增长和实际动力学偏差也未因此消失。

本轮不实现 interval sphere、连续二分、sphere-AABB 扫掠、新 ESDF 或新证据模型。不得新增“周围任意未知格就拒绝”的强包络政策，也不得反向放开既有采样点未知拒绝。

记录固定 `check_model=existing_sampled_clearance`、策略身份、实际检查范围和采样配置。这是描述，不是可切换的安全开关。

### 8.3 默认失败与阶段复用

硬检查返回至少包括 `completed`、`passed`、首个原因、曲线身份及检查时刻／物理版本。默认不通过；无 epoch、输入非法、deadline 到期或检查未完成不能使用空结果放行。

冻结规划图上的候选检查与最新相关走廊发布检查复用同一政策，但分别记录身份。最终提交前需要最新证据，不得因为算法只有一个 helper 就省略后者。

扩大旧尾段检查的**时间范围**是 R07 的必要变化；本轮不因此扩大每个点的几何证据政策为全机体已观测。

### 8.4 强包络作为独立后续项

后续只有在明确提出连续扫掠保证时，才先对起点、普通走廊、末端做一次地图适配探针，再讨论体素自由语义、误差包络、连续检查和计算成本。探针失败不应促使填未知。

此项不列本轮 D1–D4、测试门或任务到达前置条件，也不需要先写一套在线接口等待未来使用。

**验证：T3 中锁定既有离散拒绝和末端行为；不再要求 v1.0 的连续包络 T04。**

## 9. R07–R09：统一提交、接续与失效处理

### 9.1 R07：同一策略，不同时间的必要复查

保留 `IMMEDIATE / AT_TIME / CANCEL_PENDING`、accepted ID 单调性、迟到拒绝、P/V/A 接续和服务端同一时钟采样的身份规则。本轮不增加消息字段、第二个执行所有者或执行许可服务。[C6]

最终接续检查使用如下两条实际分支：

```text
切换成功：active 当前点 → t_switch → 新曲线 → 新静止末端
未激活 / 撤销：active 当前点 → active 原静止末端
```

推荐用现有 corridor 捕获机制一次收集“active 完整剩余段 + 新曲线”的现有采样及净空邻域，复用硬检查。只有到切换点的旧前缀通过，不足以支持取消后的旧停止尾段。

即使新轨迹已激活也继续监督其剩余段。旧尾段不再有效时不得称其为可靠后备；保留已有危险处理，必要时尝试从当下状态生成受检替代动作。检查条件失效不能由取消 pending 本身解决。

提交对曲线实际 payload、最新相关 corridor 和运动／时序条件负责。地图远处更新不要求无条件重做一切；相关内容变更则沿用原有有限重捕获。未成功提交／发布的候选不替换 active，pending 本地镜像不得在 server 实际拒绝后假装已激活。

### 9.2 短轨迹与接续期限

约定 `t_switch` 必须位于旧曲线有效时间内，并满足原发布余量。若窗口不足，结束本次 scheduled 尝试，不把启动模式改成立即来绕过检查。旧曲线停稳后可使用新鲜反馈发起新的立即轨迹。

保留原接续延迟和发布余量，首先允许停顿，不在本轮联动调整预算、速度、PL、地图年龄和连接时刻。确需修改某一时序参数时，单独记录变更理由和一个针对性反例。

### 9.3 R08：硬失败与质量退化分开

| 情况 | 处理 |
|---|---|
| 普通搜索／优化失败，active 条件仍有效 | 不覆盖 active，继续既定受检运动至停止端点 |
| 远端 guide 未知／没有可用局部前缀 | 不发布未知尾部；满足条件时调用 R10，否则报告阻塞 |
| advisory warning／失效／偏好未保持 | 记录质量退化；不单独急停或否决硬检查通过的候选 |
| 新障碍、执行采样点未知、motion 失效或 tracking 越界 | 原监督与保护处理；撤销不再可用的 pending，尝试受检替代动作 |
| 保护制动也失败 | 报告无新动作获准、检查依据失效；保留命令不是安全证明 |
| 时间回退／frame 契约改变 | 沿用原撤销与时钟保护，清理对应检查记录 |
| 局部静止但未达到任务终点 | 局部停止／等待，不是任务完成 |

复用现有失败字段，必要时区分 `BUDGET`、`PHYSICAL_REJECT`、`OBSERVATION_BLOCKED`、`CHECK_PRECONDITION_LOST`。不为每个诊断新建一个 FSM 状态。

### 9.4 R09：时效与桥接不变

沿用原正常运动的 quality、`allow_bridged`、map/motion age 和约 1 s 外部支持桥接限制，不因末端静止而延长。PL advisory 过期与当前运动监测过期不是一回事。[C2]

服务端末端定点命令仍可保留，但不代表无限期受检查的悬停。估计器完全停更或环境证据持续失效时，本版只保留现有保护接口和明确失效诊断，不虚构尚未实现的安全降落能力。

commit、publish、accepted、activated、实际停车、原任务到达分别记录。`passed` 不代表 server 已接收，server 到时清零不代表机体已停止。

**验证：T4、T5。**

## 10. R10–R12：一次观察恢复、风险报告与共享预算

### 10.1 R10：一个受限的观察接近函数

R10 只处理“当前正常路线因物理观测不足没有有效局部前缀”这一场景。不能把优化超时、动力学不合法、frame/motion 失效或 PL warning 都转换成观察许可。

接口形态可为 `tryObservationApproach(context, blocked_region, budget)`，返回一个观察目标／失败原因，不直接发布命令，也不另建探索器。工作流固定为：

```text
固定一个关键未知区域
→ 最多 8 个确定性位置做廉价筛选
→ 结合执行观测／已知障碍／已有连接证据筛选
→ 同一 A* 一次有界多目标执行连接搜索选 1 条路径
→ 仅对选中目标复用 EGO / 静止末端 / 硬检查 / 提交入口
→ 动作完成后观察一次实际相关证据
→ 无收益或无法求解，结束本次恢复
```

关键区域只选原终点体素或前缀首个受阻邻域；本次恢复内保持身份不变，不能通过换一个近邻 cell 不断重置尝试。

候选使用原 pool、现有约 0.5 m 量级局部候选间距和已观测位置，可以包含左右、上／下、后退及少量组合方向。最多 8 个，越界或重复的直接删除，不为凑满八个扩大池。方向依据当前起点与任务方向计算，不硬编码森林布局或“永远下移”。具体偏移表集中在一个 helper，作为工程默认记录。

只用真实传感器模型和可实现姿态筛选。通过 `T_map_lidar`、外参、水平／垂直 FOV、量程，将固定区域的少量探针点变换到候选 LiDAR frame。检查已知障碍遮挡；未知视线仅表示预期不确定。实际字段已有来源接口。[C7]

仅保留端点查询通过、预计关键观测改善为正的候选。排序按关键探针改善量优先、移动距离较小优先、固定坐标顺序处理。无需熵、Fisher 信息、未来 PL 多目标评分或历史任务价值。离散束不命中、姿态近似和未知遮挡可能使预计收益失效，因此这个分数不是观测保证。

### 10.2 观察连接也不能借未知放行

候选端点通过点查询不证明可到达。同一个 A* 引擎在一次有界多目标搜索中确定可达候选，连接目的使用执行语义的查询，不走物理未知；随后只对选中目标进行一次 EGO 求解。这不是恢复 strict advisory，advisory 仍是有限代价。

观察轨迹必须实际到达所选观察位置并静止结束，不能截在中途却记录为完成观察。最终 B-spline 仍按 R05–R09 检查。选中候选求解失败后不在同次恢复中逐个尝试第二到第八个。

只要求使用现有执行器可实现的姿态预测。没有相应消息和控制能力时，不增加任意 pitch/roll/yaw 扫描动作。传感器参数缺失或无可用候选，明确返回阻塞。

### 10.3 实际收益、退出与去重

在反馈确认观察动作完成后，消费一帧时序／位姿合法且与该动作完成相符的新观测；用关键区域实际 `unknown→free` 或 `unknown→occupied` 的变化判断是否获得信息。后者也是信息，但不是可通行，需要普通路线层重新判断。

观察等待有界，先复用当前环境新鲜度窗口作为开发等待上限；这只是流程期限，不是保证传感器一定提供数据。期限内无合法新帧记 `OBSERVATION_DATA_UNAVAILABLE`，有新帧无相关变化记 `NO_GAIN`，不虚报传感器损坏或全局不可达。

复用现有 evidence fingerprint，加一个轻量的恢复尝试记录：任务身份、固定关键区域、尝试前相关证据、候选／轨迹 ID、结果。不建立长期访问地图。

**同一阻塞事件最多执行一次观察动作。** 自己刚执行的位移、单纯 generation 递增或时间推移不自动清除已尝试状态。只有原任务变化或关键区域出现实质新证据，才重新进入正常决策；不能在 A↔B 间通过自身运动重新获得八次尝试。

预算不足时记未执行／`BUDGET`，不伪称观察无收益；不得在函数内部重建预算。没有合法、有收益的动作时，`OBSERVATION_BLOCKED` 是有效退出，不是任务完成。

### 10.4 R11：质量报告与一次有界修正

后端主线固定为“一条 guide → 沿 guide 初始化 → 原参考跟踪／平滑优化 → 最终质量评估”。不在每次优化迭代内重新预测 PL，不另建全局候选排名器。

已有求解器内部的物理可行 incumbent 可以保留，且每次求解清空、身份绑定、最终重新硬检查；本轮不把它扩展成按 PL 维护的候选库。manager 层只持有一个工作候选；尝试可选修正时允许保留原未修改值用于失败回滚，这不形成跨轮候选池。

硬检查与质量报告必须逻辑分离：

| 硬检查结果 | 质量报告 |
|---|---|
| 曲线数值、边界、静止末端、动态、物理／motion／时效、接续是否合法 | 同前缀长度、advisory 积分、有效覆盖比例、偏离与评价是否完成 |
| 未完成或失败不能提交 | `PREFERENCE_DEGRADED` / `NOT_COMPARED` 不单独否决提交 |

比较同一起点、同一停止终点的 guide 前缀与实际曲线。起点连接段计入双方对应参考，不跨版本比较旧积分。有效覆盖与缺失长度单列，不能只平均有效 PL 样本。按已有积分误差处理微小差异，不增加一排新阈值。

对本轮最终候选做一次质量评估；触发并完成一次修正后，可对修正结果再评估一次。不是所有中间阶段都追加一轮 Predictor。正常几何／动态修正与质量修正共享**一个外层修正机会**，不各自追加一次。

质量差时，可在明确剩余预算内复用已有 guide 修正；没有预算或修正失败，保留原工作值并进入必要硬检查，记录退化。不得因为 `advisory_avoid_samples`、`risk_preference_lost` 或缺失覆盖直接返回发布失败。单纯相对 guide 的偏离用于质量；真实目标错误或运动不合法仍属于硬问题。

质量计算本身无法完成时标 `NOT_COMPARED`。不得让非必需质量修正占光最终检查时间；一旦总 deadline 真正到期仍不能发布，这是计算条件失败，不应改名为 PL 危险。

### 10.5 R12：预算和状态不重复建设

保留原每轮 1.5 s 总上限、1.0 s 累计搜索上限和最多 3 个修复动作额度；原始常量、有效配置和计数方式以本地代码核对为准。`PlanningBudget` 已提供统一 deadline 和 repair 计数，不另建预算管理器。[C2,C3,C10]

冻结、搜索、前缀选择、EGO、观察恢复、可选修正和最新提交检查共享预算。模块内部不得重置计时。R11 的一次外层修正上限比总 repair 额度更窄；剩余额度可以被原有限 publication recheck 消费，不代表还能新开路线或观察候选。

观察恢复与正常曲线修正不是无条件叠加；仅满足自身触发条件才使用余量。预算不足返回具体结果。对没有相关输入变化的失败，复用现有等待机制，不靠定时重建同一请求无限重跑。

新增配置只保留物理未知代价及一个策略身份，例如 `optimistic_route_stop_lite_v1_1`；ON/OFF 沿用既有参数。数值末端容差、候选上限和偏移表集中为有注释常量，不增加多个可任意组合的安全开关。

正常循环只保留轻量结果、计时和身份；详细来源与失败 bundle 复用现有 opt-in writer，不在热点循环逐点写文件或复制全图。

**验证：T2、T5、T6。**

## 12. 轻量验证：六组定向场景、一次集成、一次完整任务

### 12.1 原则与边界

已有断言可复用就不新写测试程序。每次改动只运行相应场景及直接依赖，修复后定向重跑。最后对受影响功能和既有执行协议做一次集成。六组场景不是六次森林飞行，也不是要求连续六次成功。

本版将 v1.0 八类场景合并为六组，并移除连续包络测试。该删除与本版范围一致；与策略无关的物理、身份、时钟、来源回归不得删除或放宽。

### 12.2 六组必要场景

| ID | 构造 | 必须观察的结果 |
|---|---|---|
| T1 查询／目标／前缀 | 同一图含未知目标、已有障碍、自由前缀与未知间隙 | 未知可搜索；已知障碍始终拒绝；执行采样点未知仍拒绝；前缀不跨间隙；三个目标不混淆 |
| T2 软代价／质量 | 两条已知可行路线，包含有效、warning、缺失与长 guide 尾部；再提供一个仅 warning 的唯一通道 | 函数连续有限非减；ON/OFF 可解释；唯一 warning 通道不被封死；同前缀比较；质量退化不单独否决物理合格候选 |
| T3 实际局部曲线 | 非零起始 P/V/A，经历拟合、优化和时间调整；增加离散采样点障碍／未知反例 | 最终真实边界和逐轴动力学合法；保留原采样／尾点／越界拒绝；静止末端不等于任务到达；不靠 server 清零通过 |
| T4 接续／取消／求解失败 | 一条 active 和 pending，正常切换、迟到、取消、短曲线及后续求解失败 | ID／时钟／PVA 正确；取消后旧尾段覆盖；无非法 scheduled；输入正常时旧曲线能在反馈中按原停车容差停止 |
| T5 条件失效／预算 | 分别触发 advisory stale、motion/map stale、相关走廊改变、shared deadline 到期 | quality 与硬条件分开；不延长桥接、不重置预算、不用空检查放行；失效后不继续声称受检停止保证 |
| T6 一次观察恢复 | 真实 FOV 下的终点盲区，包含一个可用观察位置、不可达位置和无收益情况 | 仅对选中位置求解；实际到位后才评估新证据；不填自由、不改 FOV；无收益／无数据有界退出；自身移动不重置同次恢复 |

T3 只锁定本版离散政策，不假装覆盖了所有采样间薄片。T4 必须至少复用一组现有反馈仿真看真实运动，不只看最终 setpoint。T6 可以用明确标注的合成传感器 fixture；它不等于原末端现场已复现。

T2 的确定性输入可验证“代价影响选择”；单次 ON 任务无需强制走预设左／右通道。主张真实风险收益或统计覆盖须另做独立实验。

### 12.3 复用入口，不新增验收平台

优先使用已注册的 `test_ego_baseline`、`test_ego_pipeline`、`test_ego_scheduled_execution`、`test_traj_server_time`、`test_ego_full_stack_feedback` 和 replay 工具。[C9]

不强制新增两个跨包 CTest 标签。可以使用现有测试名称／GTest filter，先列出选择项，再执行一次；选择为空不能视为通过。历史 strict 搜索预期因政策改变需要更新时，标明变更原因，不改无关断言。

一份末端冻结输入最多做一次初始 replay／定位探查；原 bundle 不在本机就记缺失。不能用后来输入冒充原同帧复现，也不要求为补历史证据追加完整现场。

### 12.4 完整任务额度与退出规则

默认安排 **一次**原完整 ON 仿真，保持原 seed、起终点、300 s 上限、原到达规则、ON/prior OFF 和其余模型／物理配置。原规则判定完成后可结束，不要求继续空跑。

失败先保存首个足够重放的反例并离线定位。存在明确相关修复且定向测试通过，才安排 **一次修复重跑**。第二次仍失败，本开发批次交付 `BLOCKED`，不自动第三次、第四次运行。

相同 SHA／输入／配置没有新原因时不重复试运气。该规则限制本开发批次的自动试跑，不限制后续经明确新设计或修复建立的独立批次。

本轮不安排完整 OFF 对照，也不据单次 ON 主张统计收益。PL 校准、正式多 seed 统计和实飞均不在本轮。

### 12.5 最小证据和交付状态

正常运行只记录：策略／SHA、三个目标、guide 前缀、轨迹身份、硬检查结果、质量状态、主要耗时、观察结果和任务结果。失败时复用既有导出器保存一份必要 bundle，不逐帧保存全地图。

修复摘要固定为“输入 → 原因 → 改动 → 定向验证 → 是否需一次完整任务重跑”。无需为每次失败新增长篇审计报告。

| 状态 | 含义 |
|---|---|
| `IMPLEMENTED` | 代码和必要定向验证完成，原任务未验证或未到达 |
| `DEV_ACCEPTED` | 定向／相关集成通过，原 ON 任务按原判据真实到达，没有绕过本版硬检查 |
| `BLOCKED` | 存在可复现的实现、观测、算力或模型阻塞；明确交付，不包装成任务完成 |

本版 `DEV_ACCEPTED` 仍不是全扫掠证明、PL 统计资格或实飞认证。

## 13. 完成条件与实施约束

### 13.1 合入必须满足的条件

route 未知只获搜索资格；正常和观察轨迹真实静止结束；既有硬检查保持且默认不通过；advisory 只影响偏好／质量；旧停止授权不再与新主线叠加；取消接续时旧完整剩余段有检查依据；观察恢复一次有界；原任务和来源参数未被修改。

本轮唯一大范围重构目标是消除重复决策，不是减少文件数量。允许提取小 helper，但不要求新增地图层管理器、轨迹证书系统、候选管理器、探索 FSM 或跨进程查询服务。

### 13.2 必须保持的有效配置

保留 body radius、tracking reserve、motion budget、map resolution、H/V budget／reserve、来源噪声、prior、时效、桥接、动态约束、原任务及到达配置。读取运行配置而非只看代码默认值。

不得填未知、借真值补地图、扩大 FOV、缩小机体／误差预留或放宽时效以取得表面成功。不得因质量报告耗时就跳过硬检查，也不得用失效旧轨迹作为未检查恢复动作。

若继承的中心格观测模型仍使原场景无有效接近动作，交付具体反例。不能因已经延后强包络，就假设末端覆盖问题必然消失。

### 13.3 后续独立任务，不自动挂到本轮

完整扫掠包络与地图证据适配、定位／地图相对误差建模、PL 来源校准、非静止末端的更高速度策略、通用主动感知分别独立立项。它们不应通过“保证更科学”被悄悄重新加回 D1–D4。

后续若需要比本版更强的保证，必须同时提升模型、实现与验证，不能只改日志名称；若继续选择轻量离散方案，则应长期保持其能力边界说明。

## 14. 开发伪代码与代码代理任务说明

### 14.1 单轮伪代码

```text
on_planning_event:
    消费实际执行反馈；检查当前输入条件
    view, budget = 建立本轮唯一冻结上下文和预算
    route_goal = 原任务在本轮范围内的路线目标
    guide = 复用可用几何，或同一 A* 求一条 guide
    prefix = 按执行语义选择顺序连续的可用前缀

    若没有有效 prefix 且确为观测阻塞:
        recovery_guide = 同一 A* 一次执行语义多目标连接，优先推进／必要时观察
        candidate = 仅对连接成功目标求解静止末端曲线
    否则，若 prefix 有效:
        candidate = EGO 沿 prefix 生成静止末端曲线
    否则：记录原原因，不覆盖 active；结束

    对实际 candidate 进行硬检查与独立质量评估
    若满足有界修正条件且仍有余量:
        最多一次外层修正；更改后重新检查实际曲线
    若仍无合格 candidate:
        不覆盖 active；按真实原因报告／保护；结束

    用最新相关 corridor 检查 active 完整剩余段和 candidate
    核对 motion、P/V/A、ID、生效时间和预算
    原子提交，再按既有协议发布
    等待／消费 server 实际激活反馈；继续原监督
```

“质量评估未完成”和“硬检查未完成”分别处理。前者可以记录 `NOT_COMPARED`，后者不能放行。观察动作完成后的单次证据判断由原 FSM 消费新输入完成，不在同步规划函数内阻塞等待传感器。

### 14.2 可直接交给代码代理的约束

> 按本文件 v1.1 而不是叠加 v1.0 实施。固定审阅 SHA，核对本地差异，依次完成 D1→D4。复用一张 GridMap、同一 A*／EGO、PlanningView／PlanningBudget 和 active/pending 协议。只放开路线层的物理未知，保留原实际曲线采样／净空／观测／motion／时效检查；不实现完整连续扫掠包络及其前置探针。正常和观察曲线都具有真实静止末端，完成后移除正常非零末速和直线停止空间的重复授权。advisory 统一为有限代价，质量结果不能单独否决提交。观察恢复最多八个廉价位置筛选、一个完整连接求解和一个动作；不扩展候选池或探索器。保留 pending 撤销后旧尾段的检查。按六组场景定向验证、相关集成一次、原 ON 任务一次；有明确修复才允许一次重跑，仍失败就交付 BLOCKED。不得改任务、传感器、来源模型、物理预留或时效来取得表面成功。
